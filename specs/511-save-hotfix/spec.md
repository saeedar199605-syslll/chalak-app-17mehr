## Confirmed source causes / exact fix
The v5.1.1 lazy audit-JSON optimization remains. Expanded evaluation patches reuse stored objects, but Admin validation and merge still repeatedly serialized unchanged evaluations. Now unchanged stored references skip redundant comparisons, while all incoming changed records still pass the original validation and shared context is loaded once. Evaluation audit entries now accumulate separately before one concatenation with existing history; avoids shifting up to 10,000 historical entries for every imported evaluation without changing ordering/retention. Import callbacks supply changed evaluations, reducing full-array diff work.

MIS pending/error messages were behind the raised confirmation dialog; failures left confirmation open with no visible cause. The dialog now shows pending/error state, disables confirm/back while pending and reports actual saved/rejected counts after acceptance. Prepared preview remains on failure. Managed 503/network uncertainty performs one authenticated receipt read (GET /api/state?operationId=...) using actor-bound existing receipts before reporting success; never a success without receipt or POST acceptance. Existing receipt payload/actor guards, revision checks, permission/source validation and KV commit order remain unchanged. push sync awaits its network promise before clearing isSyncing, preventing overlapping synchronization while the request is pending.
